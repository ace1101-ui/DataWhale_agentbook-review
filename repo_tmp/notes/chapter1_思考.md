## 1、Agent 的组成

之前就了解过，agent 其实就是 **model + harness**，其中的 model 就是我们熟悉的 LLM。这个 LLM 是作为 agent 的大脑，进行思考，但不具备类似"爪子"一样的手脚。所以 **harness 应该是"模型之外、让 AI 能稳定干活的一整套工程系统"**；我查过这个说法最早由 HashiCorp 联合创始人 Mitchell Hashimoto 在 2026 年 2 月 5 日命名，并由 OpenAI 在 2026 年 2 月 11 日推广。

## 2、何为 harness？

harness 中文意思是"马鞍"。就如文中提到的另一个公司所言：agent = LLM + 上下文 + 工具，harness 应该包括但不限于提供上下文、工具的功能。但其实我研读过一些其他技术论文，harness 工程应该还有这些功能：

典型包括：

- **Agent 循环编排**：决定下一步做什么、何时停止。
- **工具调用**：比如说搜索、文件、API、终端、数据库等。
- **上下文与记忆管理**：维护会话状态、长期记忆、短期记忆等。
- **执行环境与沙箱**：提供文件系统、依赖、权限隔离。
- **校验与护栏**：输出格式检查、权限控制、内容过滤。
- 等等。

文中还有形象比喻：**agent = 大脑 + 眼睛 + 手脚**。

## 3、什么是工具调用？

工具调用（Tool Calling，也称 Function Calling）。从文中看大概分为以下部分：

1. 第一步：声明工具
2. 第二步：模型决定调用
3. 第三步：结果追加到上下文
4. 第四步：模型基于结果回复

## 4、影响 agent 能力的几个常见来源

1. 任务里的上下文
2. 你提供的外部指令或者 SOP、文档等，因为会有检索增强生成（RAG）然后返回给 LLM。
3. LLM 的参数，模型权重等等。

## 5、什么是 ReAct？

读过这个 agentbook 文章后我知道了，ReAct 是 **Reasoning（推理）+ Acting（行动）**。在真实的 agent 工作流程中：模型先思考当前应该做什么，然后调用工具行动，再观察工具返回的结果并继续思考下一步。这个"**想 → 做 → 看 → 想 → 做 → 看**"的循环不断重复，直到任务完成。

## 补充思考

除了以上这些小总结，其实我也通过这篇文章知道了：之前有过 **提示词工程 → 上下文工程 → harness 工程 → loop 工程**，还有人提出 **graph 工程** 的演进过程，但也不是替代关系，而是根据应用场景去选择。

另外，在工作流模式的发展上，也有从 **纯工作流到 auto-agent** 的发展：前者是固定的工作流，后者是模型自己去决策。区别的话，一个是按固定路径去实施，而另一个没有预先定义的路径，而是根据环境反馈实时决定。

此外，我觉得这个第一章对我比较有帮助的，就是有一个关于**国内流行的搭建 agent 的方式**的介绍。我个人早些时间是接触的 **Coze / Dify**、以及 **Pi agent**，还有 **LangChain / LangGraph** 开源框架；后面也自己简单研究了 **dsh**。其他的框架或者范例我后面有时间再去研究研究。
